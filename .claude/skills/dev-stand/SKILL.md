# Дев-стенд TasksFlow

```bash
bash .claude/skills/dev-stand/stand.sh          # поднять: около минуты в первый раз, потом секунды
bash .claude/skills/dev-stand/stand.sh status   # работает ли
bash .claude/skills/dev-stand/stand.sh logs 100 # хвост лога сервера
bash .claude/skills/dev-stand/stand.sh down     # остановить
bash .claude/skills/dev-stand/stand.sh reset    # пересоздать базу с нуля и поднять заново
```

`up` по шагам:

1. Ставит и запускает MariaDB 10.11 с временем МСК.
2. Создаёт базу `tasksflow_dev` и пишет `.env` с меткой стенда. Чужой `.env` без метки не трогает,
   бот выключен через `TELEGRAM_MODE=off`.
3. Делает `npm ci`, если менялся lock-файл.
4. Строит схему. Таблицы `users/companies/workers/tasks` берутся из `shared/schema.ts` через
   `drizzle-kit export`: он только печатает SQL и к базе не подключается. Остальное накатывают
   те же скрипты `script/`, что и деплой, в его порядке: список читается из `deploy.yml`.
   Повторно схема перестраивается, только если менялись `shared/schema.ts`, `script/` или `deploy.yml`.
5. Запускает `npm run dev` и заводит демо через настоящий API: компания «Тёплый хлеб (демо)»,
   4 сотрудника, 6 задач.

Логи — в `output/dev-stand/`.

- Адрес: **http://localhost:5000**.
- Вход: `+79990000001`, PIN `4826`. Это админ и root.
  Сотрудники: `+79990000002`…`05`, PIN `5937` / `6048` / `7159` / `8260`.
  Через API: `curl -c /tmp/jar -H 'content-type: application/json' -d '{"phone":"+79990000001","pin":"4826"}' localhost:5000/api/auth/login`.
  У входа лимит 10 попыток за 15 минут: сессию стоит переиспользовать.
- Демо-кабинет без сервера и входа: `/demo`.
- База: `mariadb --protocol=socket -uroot tasksflow_dev`.

Ускорить первый запуск: `cloud-setup.sh` рядом — это setup-скрипт облачного окружения. Его вставляют в настройки окружения (claude.ai/code → окружение → Edit → Setup script), и MariaDB с настройками МСК попадает в снапшот. Без него стенд ставит MariaDB сам, это дольше на 20 секунд.

## Правила

- **`setup-db`, `db:push`, `drizzle-kit push` не запускать даже на стенде**: правила проекта
  запрещают их после потери базы 28.04.2026. Новая колонка — новый точечный скрипт в `script/`
  и строка в `deploy.yml`, стенд подхватит его сам.
- Стенд только для облачного контейнера и только для баз `*_dev` на 127.0.0.1. На прод — скилл `prod`.
- UI smoke с подменённым API (`npm run build && npm run smoke`) по-прежнему проверяет вёрстку
  без сервера. Стенд нужен, когда важно поведение настоящего API и базы.
- Снимки — скилл `visual-check`, он сам входит под админом. На страницах кабинета
  `networkidle` не наступает (живые обновления `/api/events`), поэтому ждём `load` и скелетоны.
