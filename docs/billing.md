# Оплата тарифов: Робокасса

Админ компании оплачивает тариф сам: меню → «Тариф и оплата»
(`/admin/billing`). Картой или СБП через Робокассу — в окне поверх страницы,
а если окно не загрузилось, обычной страницей кассы. После оплаты тариф
продлевается сразу, без участия людей. Галочкой можно включить
автопродление.

| Что | Где |
|---|---|
| Цены, сроки, пересчёт срока, правило автопродления | `shared/billing.ts` |
| Подписи, параметры, чек, повторное списание | `server/billing/robokassa.ts` |
| Заказ, ResultURL, автопродление | `server/billing/service.ts` |
| Таблицы | `server/billing/store.ts`, `script/_add-billing.ts` (`npm run add-billing`, шаг деплоя) |
| API | `server/billing-routes.ts` |
| Страница оплаты | `client/src/pages/Billing.tsx` |
| Цены и платежи для root | Root → «Компании» (`client/src/components/RootBillingPanel.tsx`) |
| Оферта | `content/legal/offer.md` → `/offer` |
| Проверки | `tests/billing.test.ts`, `script/smoke-billing.js` (9-я сессия `npm run smoke`) |

## Подключение магазина

1. **Реквизиты.** Робокасса проверяет сайт: оферту, цены, контакты и
   реквизиты. Задайте GitHub Secrets `LEGAL_OPERATOR_NAME`,
   `LEGAL_OPERATOR_INN`, `LEGAL_OPERATOR_OGRN`, `LEGAL_OPERATOR_ADDRESS` (и при
   желании `LEGAL_CONTACT_EMAIL`), запустите Actions → Deploy → Run workflow и
   проверьте, что на https://tasksflow.ru/offer и /privacy нет плейсхолдеров.
   Текст оферты стоит показать юристу.
2. **Магазин.** robokassa.ru → регистрация → «Мои магазины» → добавить
   магазин с сайтом tasksflow.ru. Для заявки: оферта —
   https://tasksflow.ru/offer, цены — https://tasksflow.ru/#pricing,
   описание услуги — доступ к сервису задач по подписке.
3. **Технические настройки магазина:**

   | Поле | Значение |
   |---|---|
   | Алгоритм расчёта хеша | MD5 (другой — задайте его в `ROBOKASSA_HASH`) |
   | Result URL | `https://tasksflow.ru/api/billing/robokassa/result`, метод **POST** |
   | Success URL | `https://tasksflow.ru/billing/success`, метод GET (POST тоже работает) |
   | Fail URL | `https://tasksflow.ru/billing/fail`, метод GET |

   Там же — Пароль #1 и Пароль #2, и отдельная пара тестовых паролей.
4. **Секреты.** GitHub → Settings → Secrets and variables → Actions:

   | Секрет | Значение |
   |---|---|
   | `ROBOKASSA_MERCHANT_LOGIN` | идентификатор магазина |
   | `ROBOKASSA_PASSWORD1`, `ROBOKASSA_PASSWORD2` | боевые пароли |
   | `ROBOKASSA_TEST_PASSWORD1`, `ROBOKASSA_TEST_PASSWORD2` | тестовые пароли |
   | `ROBOKASSA_IS_TEST` | `1` — тестовый режим, `0` — боевой |

   Actions → Deploy → Run workflow: деплой запишет их в `.env` сервера (в
   логе — только имена). Пустой секрет ничего не меняет, поэтому
   выключать — значением `0`, а не удалением.
5. **Тестовый платёж.** Под админом компании: «Тариф и оплата» → «Перейти
   к оплате» → тестовая оплата в окне Робокассы. Страница покажет «Оплата
   получена», тариф продлится, платёж появится у root в «Компании → Платежи»
   с пометкой «тест», а владелец получит сообщение в Telegram (если заданы
   `ALERT_TELEGRAM_*`).
6. **Боевой режим.** `ROBOKASSA_IS_TEST=0` и снова Run workflow. Тестовые
   заказы так и останутся тестовыми: их подпись проверяется тестовыми паролями.

Пока логина или пароля текущего режима нет, кнопки оплаты нет. Админы видят
«Онлайн-оплата скоро появится» с адресом поддержки.

### Чеки (54-ФЗ)

Если чеки бьёт Робокасса («Робочеки») или ваша касса через неё, задайте
`ROBOKASSA_SEND_RECEIPT=1`. Тогда в оплату уходит позиция «TasksFlow, тариф
«Команда» на 1 месяц» — полный расчёт, услуга. При необходимости задайте
`ROBOKASSA_RECEIPT_SNO` (система налогообложения, например `usn_income`) и
`ROBOKASSA_RECEIPT_TAX` (ставка, по умолчанию `none`). Включайте, только
когда фискализация в магазине подключена, иначе Робокасса отклонит подпись.
`Receipt` уходит URL-кодированным JSON — той же строкой, по которой
считается подпись (как в примере формы у Робокассы). Включив чеки, сделайте
тестовый платёж и проверьте чек.

### Автопродление

Рекуррентные платежи Робокасса подключает магазину отдельно, по заявке в
поддержку («периодические платежи»). Пока их нет, галочки на странице
оплаты нет. После подключения задайте `ROBOKASSA_RECURRING=1`.

Как это работает:

- Галочка «Я согласен на автоматические списания…» по умолчанию не стоит.
  Рядом — сумма, периодичность и ссылка на раздел оферты «Автопродление».
  Согласие пишется в `payment_consents`: текст, редакция оферты, IP и
  браузер. Отказ — отдельная строка.
- Первый платёж с галочкой — «родитель» серии: Робокасса запоминает карту.
  Сумма серии фиксируется. Новая цена в Root её не меняет, для этого нужно
  предупредить людей за 14 дней (оферта).
- За 3 дня до списания админам уходит предупреждение (push, Telegram,
  почта). Списание — в последние сутки оплаченного срока (`chargeAt`):
  сервер отправляет `POST https://auth.robokassa.ru/Merchant/Recurring` с
  `PreviousInvoiceID`. Ту же дату показывают страница оплаты и
  предупреждение. Тариф продлевается, когда Робокасса подтвердит оплату на
  ResultURL.
- Отказ кассы — новая попытка через сутки, всего 3. Потом автопродление
  выключается, админы и владелец получают сообщение. Попытку «занимает»
  условный UPDATE: два процесса (перезапуск при деплое) карту дважды не
  спишут.
- Касса не ответила (таймаут, 5xx) — это не отказ: заказ ждёт уведомления
  (оно засчитается и позже), владелец получает предупреждение проверить
  операцию в кабинете кассы.
- Автосписание, подтверждённое уже после отключения или замены серии,
  тариф не меняет. Админам приходит «Вернём автосписание», владельцу —
  напоминание вернуть деньги в кабинете Робокассы (оферта: 10 рабочих дней).
- Отключить: «Тариф и оплата» → «Отключить автопродление». Действует
  сразу, оплаченный срок остаётся.
- Разовая оплата другого тарифа или срока выключает старую серию, иначе
  следующее списание вернуло бы прежний тариф. Любая ручная правка тарифа в
  Root тоже её выключает. Каждое выключение — строка в `payment_consents`.

Расписание — минутный планировщик сброса задач
(`server/daily-scheduler.ts`): шаг оплаты раз в 10 минут, фоном и со своим
замком, чтобы медленная касса не задерживала сброс и напоминания.
Неоплаченные заказы через 3 дня помечаются «не оплачен».

## Цены

Root → «Компании» → «Цены тарифов»: тариф × срок (1, 3, 6 или 12 месяцев) ×
цена в рублях. Лендинг и страница оплаты подхватывают изменения в течение
30 секунд. У тарифа без цены на лендинге «по запросу», онлайн его не купить.
Миграция создаёт одну цену — «Команда» за 990 ₽ в месяц, как было на лендинге.

Срок при оплате (`planAfterPayment`):

- тот же тариф — новый период прибавляется к оставшемуся;
- другой тариф — оставшиеся дни пересчитываются по цене месяца (10 дней
  «Команды» за 990 ₽ превращаются в 5 дней тарифа за 1 980 ₽) и
  прибавляются к новому периоду;
- тариф, подключённый root бессрочно, онлайн не оплачивается.

## Безопасность

- Сумму считает только сервер, по ценам из БД. Сумма с клиента — сверка:
  если цена изменилась, пока форма была открыта, заказ не создаётся (409).
- Оплата засчитывается только по уведомлению на ResultURL: подпись Паролем
  #2, сумма совпадает с заказом. Переход заказа в «оплачен» вместе с
  продлением тарифа — одна транзакция с блокировкой строк, повтор
  уведомления просто получает `OK{InvId}`.
- Статус заказа видит только админ той же компании.
- Окно оплаты Робокасса открывает SuccessURL внутри своей рамки на нашей
  странице: для `/billing/success` и `/billing/fail` — `X-Frame-Options:
  SAMEORIGIN` вместо `DENY`, и страница сама выходит из рамки.
- Ключи и пароли — только в секретах и `.env`, не в репозитории (он
  публичный).

## Приложения для телефонов

В iOS-приложении и Android-приложении (TWA) «Тариф и оплата» показывает
только тариф, автопродление и платежи — без цен, кнопок и упоминаний оплаты.
Правила App Store (3.1.1) и Google Play не разрешают продавать подписку мимо
их встроенных покупок. Сервер тоже отклоняет заказ с User-Agent iOS-приложения
(`TasksFlowApp/…`).

## Оплата по счёту и возвраты

- По счёту: root ставит тариф и срок вручную — «Компании» → строка компании.
- Возврат: в кабинете Робокассы (операции → возврат), затем root
  поправляет срок тарифа. Сумма — по разделу оферты «Возврат».
