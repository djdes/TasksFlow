# Оплата тарифов: Робокасса

Админ компании оплачивает тариф сам: меню → «Тариф и оплата»
(`/admin/billing`). Картой или СБП через Робокассу — в окне поверх страницы,
а если окно не загрузилось, обычной страницей кассы. После оплаты тариф
продлевается сразу, без участия людей. Галочкой можно включить
автопродление. Организация или ИП может оплатить по счёту, к каждой оплате
выпускается УПД. Скидки дают акции, промокоды и постоянные скидки; баланс
в баллах пополняют заранее и платят им за тариф.

## Подключение магазина

1. **Реквизиты.** Робокасса проверяет сайт: оферту, цены, контакты и
   реквизиты. Задайте GitHub Secrets `LEGAL_OPERATOR_NAME`,
   `LEGAL_OPERATOR_INN`, `LEGAL_OPERATOR_OGRN`, `LEGAL_OPERATOR_ADDRESS` (и при
   желании `LEGAL_CONTACT_EMAIL`), запустите Actions → Deploy → Run workflow и
   проверьте, что на https://tasksflow.ru/offer и /privacy нет плейсхолдеров.
   Текст оферты стоит показать юристу.
2. **Магазин.** robokassa.ru → регистрация → «Мои магазины» → добавить
   магазин с сайтом tasksflow.ru. Для заявки: оферта —
   https://tasksflow.ru/offer, цены — https://tasksflow.ru/#pricing,
   описание услуги — доступ к сервису задач по подписке.
3. **Технические настройки магазина:**

   | Поле | Значение |
   |---|---|
   | Алгоритм расчёта хеша | MD5 (другой — задайте его в `ROBOKASSA_HASH`) |
   | Result URL | `https://tasksflow.ru/api/billing/robokassa/result`, метод **POST** |
   | Success URL | `https://tasksflow.ru/billing/success`, метод GET (POST тоже работает) |
   | Fail URL | `https://tasksflow.ru/billing/fail`, метод GET |

   Там же — Пароль #1 и Пароль #2, отдельная пара тестовых паролей и
   Пароль #3 (нужен только для возвратов кнопкой из TasksFlow). Все три
   адреса с кнопкой «скопировать» есть в Root → «Компании» → «Касса».
4. **Секреты.** GitHub → Settings → Secrets and variables → Actions:

   | Секрет | Значение |
   |---|---|
   | `ROBOKASSA_MERCHANT_LOGIN` | идентификатор магазина |
   | `ROBOKASSA_PASSWORD1`, `ROBOKASSA_PASSWORD2` | боевые пароли |
   | `ROBOKASSA_TEST_PASSWORD1`, `ROBOKASSA_TEST_PASSWORD2` | тестовые пароли |
   | `ROBOKASSA_PASSWORD3` | Пароль #3 — возвраты через API (необязательно) |
   | `ROBOKASSA_IS_TEST` | `1` — тестовый режим, `0` — боевой |

   Actions → Deploy → Run workflow: деплой запишет их в `.env` сервера (в
   логе — только имена). Пустой секрет ничего не меняет, поэтому
   выключать — значением `0`, а не удалением. После выкладки в логе Deploy
   есть строки `>>> оплата: …` — ResultURL, SuccessURL, API и оферта
   отвечают как надо (`WARNING` — что-то не так, сайт при этом не
   откатывается).
5. **Проверка подключения.** Root → «Компании» → «Касса»: галочки
   показывают, какие секреты заданы (только да/нет, значения на страницу не
   попадают). «Проверить подключение» спрашивает кассу о заведомо
   несуществующем заказе (OpStateExt): ответ «не найдено» значит, что логин
   и Пароль #2 верны. Пароль #1 так не проверить — только тестовым платежом.
   Если касса ещё не приняла магазин в работу, ответ может быть другим —
   текст ответа показывается как есть.
6. **Тестовый платёж.** Под админом компании: «Тариф и оплата» → «Перейти
   к оплате» → тестовая оплата в окне Робокассы. Страница покажет «Оплата
   получена», тариф продлится, платёж появится у root в «Компании → Платежи»
   с пометкой «тест», а владелец получит сообщение в Telegram (если заданы
   `ALERT_TELEGRAM_*`).
7. **Боевой режим.** `ROBOKASSA_IS_TEST=0` и снова Run workflow. Тестовые
   заказы так и останутся тестовыми: их подпись проверяется тестовыми паролями.

Пока логина или пароля текущего режима нет, кнопки оплаты нет. Админы видят
«Онлайн-оплата скоро появится» с адресом поддержки.

### Чеки (54-ФЗ)

Если чеки бьёт Робокасса («Робочеки») или ваша касса через неё, задайте
`ROBOKASSA_SEND_RECEIPT=1`. Тогда в оплату уходит позиция «TasksFlow, тариф
«Команда» на 1 месяц» — полный расчёт, услуга. При необходимости задайте
`ROBOKASSA_RECEIPT_SNO` (система налогообложения, например `usn_income`) и
`ROBOKASSA_RECEIPT_TAX` (ставка, по умолчанию `none`). Включайте, только
когда фискализация в магазине подключена, иначе Робокасса отклонит подпись.
`Receipt` уходит URL-кодированным JSON — той же строкой, по которой
считается подпись (как в примере формы у Робокассы). Включив чеки, сделайте
тестовый платёж и проверьте чек.

### Автопродление

Рекуррентные платежи Робокасса подключает магазину отдельно, по заявке в
поддержку («периодические платежи»). Пока их нет, галочки на странице
оплаты нет. После подключения задайте `ROBOKASSA_RECURRING=1`.

Как это работает:

- Галочка «Я согласен на автоматические списания…» по умолчанию не стоит.
  Рядом — сумма, периодичность и ссылка на раздел оферты «Автопродление».
  Согласие пишется в `payment_consents`: текст, редакция оферты, IP и
  браузер. Отказ — отдельная строка.
- Первый платёж с галочкой — «родитель» серии: Робокасса запоминает карту.
  Сумма серии фиксируется. Новая цена в Root её не меняет, для этого нужно
  предупредить людей за 14 дней (оферта).
- За 3 дня до списания админам уходит предупреждение (push, Telegram,
  почта). Списание — в последние сутки оплаченного срока (`chargeAt`):
  сервер отправляет `POST https://auth.robokassa.ru/Merchant/Recurring` с
  `PreviousInvoiceID`. Ту же дату показывают страница оплаты и
  предупреждение. Тариф продлевается, когда Робокасса подтвердит оплату на
  ResultURL.
- Отказ кассы — новая попытка через сутки, всего 3. Потом автопродление
  выключается, админы и владелец получают сообщение. Попытку «занимает»
  условный UPDATE: два процесса (перезапуск при деплое) карту дважды не
  спишут.
- Касса не ответила (таймаут, 5xx) — это не отказ: заказ ждёт уведомления
  (оно засчитается и позже), а сверка с кассой засчитает его сама, если
  списание прошло. Владелец получает предупреждение.
- Автосписание, подтверждённое уже после отключения или замены серии,
  тариф не меняет. Админам приходит «Вернём автосписание», владельцу —
  напоминание вернуть деньги: root → «Платежи» → «Вернуть деньги» (оферта:
  10 рабочих дней).
- Серия, начатая в тестовом режиме, и списывается тестово (`IsTest=1`,
  тестовый Пароль #1) — автопродление можно проверить без денег, если
  Робокасса включила магазину рекуррент. После перехода в боевой режим
  (`ROBOKASSA_IS_TEST=0`) тестовая серия не списывается, а выключается:
  иначе она продлевала бы тариф даром.
- Отключить: «Тариф и оплата» → «Отключить автопродление». Действует
  сразу, оплаченный срок остаётся.
- Разовая оплата другого тарифа или срока выключает старую серию, иначе
  следующее списание вернуло бы прежний тариф. Любая ручная правка тарифа в
  Root тоже её выключает. Каждое выключение — строка в `payment_consents`.

Расписание — минутный планировщик сброса задач
(`server/daily-scheduler.ts`): шаг оплаты раз в 10 минут, фоном и со своим
замком, чтобы медленная касса не задерживала сброс и напоминания.
Неоплаченные заказы через 3 дня помечаются «не оплачен».

## Сверка с кассой

Уведомление на ResultURL может не дойти: неверный адрес в настройках
магазина, сбой сети, выкладка в эту секунду. Чтобы человек не остался без
оплаченного тарифа, «ожидает оплаты» сверяется с кассой —
`OpStateExt` (`MerchantLogin`, `InvoiceID`, подпись
`MerchantLogin:InvoiceID:Пароль#2`, как в официальном плагине Робокассы):

- в тике оплаты — боевые заказы старше 2 минут: первый час раз в 5 минут,
  первые сутки раз в час, дальше раз в 6 часов, до 10 заказов за тик;
- пока человек ждёт на странице оплаты — в фоне при опросе статуса, не чаще
  раза в 30 секунд на заказ;
- по кнопке «Проверить в кассе» у платежа в Root.

State 100 («оплачено») засчитывается так же, как уведомление: та же
транзакция, то же продление, тот же «OK» на позднее уведомление. Владелец
при этом получает в Telegram «Уведомление на ResultURL не пришло» —
проверьте Result URL в «Технических настройках». State 10 («отменена») —
заказ «не оплачен», 50 («зачисляется») — ждём. Если IncSum меньше суммы
заказа, оплата не засчитывается, владельцу уходит предупреждение. Тестовые
заказы касса через OpStateExt не показывает, их сверка не трогает.
«Захват» сверки — условный UPDATE `checked_at`: параллельные тики и опросы
не спрашивают кассу дважды.

## Напоминания об окончании тарифа

Если срок оплачен онлайн и автопродления нет, админы получают «Тариф скоро
закончится» за 3 дня до конца срока и «Тариф закончился» в течение суток
после (push, Telegram, почта) — по одному разу на срок (`company_billing.expiry_notice_for`,
`expired_notice_for`, условный UPDATE). С автопродлением вместо них —
«Скоро продление тарифа». Тариф, который root поставил вручную (по счёту),
напоминаний не получает: его продлевают так же вручную. Тарифы,
закончившиеся больше суток назад, тоже — выкладка не разошлёт письма по
старым компаниям.

## Цены

Root → «Компании» → «Цены тарифов»: тариф × срок (1, 3, 6 или 12 месяцев) ×
цена в рублях. Лендинг и страница оплаты подхватывают изменения в течение
30 секунд. У тарифа без цены на лендинге «по запросу», онлайн его не купить.
Миграция создаёт одну цену — «Команда» за 990 ₽ в месяц, как было на лендинге.

Срок при оплате (`planAfterPayment`):

- тот же тариф — новый период прибавляется к оставшемуся;
- другой тариф — оставшиеся дни пересчитываются по цене месяца (10 дней
  «Команды» за 990 ₽ превращаются в 5 дней тарифа за 1 980 ₽) и
  прибавляются к новому периоду;
- тариф, подключённый root бессрочно, онлайн не оплачивается.

## Безопасность

- Сумму считает только сервер, по ценам из БД. Сумма с клиента — сверка:
  если цена изменилась, пока форма была открыта, заказ не создаётся (409).
- Оплата засчитывается по уведомлению на ResultURL (подпись Паролем #2,
  сумма совпадает с заказом) или по сверке с кассой — нашему HTTPS-запросу
  OpStateExt с подписью Паролем #2; сумма привязана к InvId подписью формы
  оплаты. Переход заказа в «оплачен» вместе с продлением тарифа — одна
  транзакция с блокировкой строк, повтор уведомления просто получает
  `OK{InvId}`. Возвращённый заказ повторное уведомление не «оплачивает».
- Диагностика для root показывает только, задан ли секрет, — не значение.
- Статус заказа видит только админ той же компании.
- Окно оплаты Робокасса открывает SuccessURL внутри своей рамки на нашей
  странице: для `/billing/success` и `/billing/fail` — `X-Frame-Options:
  SAMEORIGIN` вместо `DENY`, и страница сама выходит из рамки.
- Ключи и пароли — только в секретах и `.env`, не в репозитории (он
  публичный).

## Приложения для телефонов

В iOS-приложении и Android-приложении (TWA) «Тариф и оплата» показывает
только тариф, автопродление и платежи — без цен, кнопок и упоминаний оплаты.
Правила App Store (3.1.1) и Google Play не разрешают продавать подписку мимо
их встроенных покупок. Сервер тоже отклоняет заказ с User-Agent iOS-приложения
(`TasksFlowApp/…`).

## Промокоды

Root → «Компании» → «Промокоды»: код (латиница, цифры, `-`, `_`; хранится в
верхнем регистре), скидка в процентах или рублях, срок, лимит оплат,
«только для первой оплаты компании», персональный код для компании (её
номер). Код и размер скидки после создания не меняются — на них могли
сослаться в рассылке; выключить, продлить или поменять лимит можно.
Кнопка «Ссылка» копирует `https://tasksflow.ru/admin/billing?promo=КОД`:
код подставится и применится сам.

- Скидку считает только сервер (`quoteOrder`), клиент показывает тот же
  расчёт из `POST /api/billing/promo` (20 проверок за 10 минут на
  компанию). В заказе — `base_rub`, `discount_rub`, `promo_code`.
- Скидка — на один платёж. Серия автопродления дальше списывает полную
  цену: так написано рядом с галочкой, в истории согласий («Первый платёж —
  N ₽ по промокоду») и в оферте.
- Одна компания использует код один раз. Окончательная проверка лимита,
  «один раз», «только первая оплата» — в одной транзакции с созданием
  заказа под блокировкой строки кода (`store.placeOrder`): два
  одновременных запроса не обойдут лимит. Использование «держат»
  оплаченные заказы, неоплаченные счета и заказы, ждущие оплаты меньше
  часа (`PROMO_HOLD_SEC`): брошенная оплата не заберёт код навсегда.
- Промокод на 100 % включает тариф сразу, без кассы (`payment_method =
  promo`, сумма 0, без автопродления и без УПД) — работает, даже пока
  Робокасса не подключена.

## Акции

Root → «Компании» → «Акции»: название (его видят на сайте), скидка 1–90 %,
даты «с» и «по» включительно по Москве (окно `[starts_at, ends_at)`).
Скидку и начало после создания не меняем — их уже видели на сайте;
выключить можно в любой момент.

- Действует самая большая; при равной — та, что идёт дольше
  (`pickPromotion`). Скидка — на все тарифы и сроки, от цены тарифа.
- Видна на лендинге (зачёркнутая цена, плашка с датой) и на странице
  оплаты; в заказе — снимок `promotion_id`, `promotion_percent`,
  `promotion_discount_rub`. Промокод и постоянная скидка считаются от
  цены с акцией.
- Только на этот платёж: серия автопродления списывает полную цену (как с
  промокодом). Список акций кешируется на 30 секунд, как цены.

## Постоянные скидки

Промокод с галочкой «Постоянная скидка» (до 50 %, можно со сроком в
месяцах): после оплаты с ним скидка закрепляется за компанией
(`company_discounts`, по строке на код — прежние остаются) и дальше
применяется сама; если их несколько — выгоднейшая на эту сумму:

- ко всем оплатам тарифа картой и по счёту — без ввода кода; такие заказы
  `discount_source = lifetime` и не тратят использования кода;
- к автосписаниям: сумма серии минус скидка, если она действует в день
  списания; так же — в предупреждении за 3 дня.

Код и постоянная скидка не суммируются: применяется выгоднейшая, при равных
— постоянная (код не потратится). Возврат оплаты, которая дала скидку,
снимает только её; root может снять скидку сам — Root → «Постоянные
скидки». Тестовый платёж (касса в тестовом режиме) скидку не закрепляет.

## Баланс и баллы

1 балл = 1 ₽. Баланс — `company_billing.balance_rub`; каждое изменение —
строкой `balance_transactions` в той же транзакции, под блокировкой строки
баланса, с ключом повтора (`dedupe_key`) и без ухода в минус. Что
проводится на каждом шаге — `server/billing/ledger.ts`.

- **Пополнение** — «Тариф и оплата» → «Баланс»: 500–300 000 ₽, картой
  (заказ `order_kind = topup`, в чеке признак «аванс») или по счёту. Баллы
  начисляются в транзакции оплаты (`topup:{id}`), повтор уведомления не
  начисляет второй раз. По пополнению выпускается УПД «предоплата».
  Тестовый платёж (касса в тестовом режиме) баллов не начисляет: иначе
  они остались бы настоящими и после выхода из теста.
- **Оплата баллами** — галочка «Списать баллы»: баллы занимаются в той же
  транзакции, что и заказ (`order_spend:{id}`, заказ `points_state = held`);
  остаток — деньгами, а если баллов хватило — тариф сразу
  (`payment_method = balance`, без кассы, без автопродления и без УПД).
  Сумма с баллами — в `expectedRub`: изменился баланс — 409.
- Не оплачен за 3 дня или начат новый заказ с баллами — баллы назад
  (`order_release:{id}`). Забирать чужие баллы может только новый заказ с
  баллами и только у брошенной оплаты картой: пополнение и счёт их не
  трогают, заказ «баллами», который ещё зачитывается, тоже (двойной клик
  получит 409). Баллы брошенной оплаты картой на странице считаются
  доступными. Брошенный заказ всё же оплатили — баллы списываются снова,
  а если их уже нет (`short`), тариф всё равно продлевается и владелец
  получает сообщение.
- По счёту, при автопродлении и в тестовом режиме кассы (оплата без денег)
  баллы не списываются.
- **Возвраты**: деньги за заказ с баллами — баллы назад
  (`order_refund:{id}`); «Отменить оплату» у заказа, оплаченного
  баллами, — баллы назад и срок как до оплаты, без кассы; возврат
  пополнения сначала списывает его баллы с баланса (не хватает — 409),
  касса отменила возврат — баллы назад. Деньги за пополнение вернули мимо
  нас (в кабинете кассы) — списываем, сколько есть, недостачу — владельцу.
- Root → «Балансы компаний»: у кого есть баллы, история, корректировка
  (+/−, с причиной — её видит компания). Root видит свободные баллы и
  отдельно — занятые брошенной оплатой; компания — их сумму.

## Реквизиты по ИНН

Кнопка «Заполнить по ИНН» в реквизитах компании: `POST
/api/billing/requisites/lookup` → подсказки DaData (`findById/party`,
головная организация). Подставляет вид (организация/ИП), название, КПП,
ОГРН, адрес, руководителя; ликвидированная организация — предупреждение.
Ключ — секрет `DADATA_API_KEY` (GitHub Secrets → `.env`); без него кнопки
нет. 20 запросов за 10 минут на компанию, любая ошибка — «заполните
вручную».

## Оплата по счёту (юрлица и ИП)

Включается, когда заполнены реквизиты Исполнителя (ниже). Админ выбирает
«Счёт для юрлица или ИП», вводит реквизиты компании (ИНН и ОГРН
проверяются по контрольным цифрам, у организации обязателен КПП) и
получает счёт PDF.

- Счёт — заказ `payment_method = invoice` без кассы, действует 7 дней.
  Повтор на те же условия возвращает тот же счёт, другой тариф или срок
  отменяет прежний. Счёт не «протухает» через 3 дня, как ссылка кассы, и
  не сверяется с кассой.
- Владелец получает в Telegram «Счёт №… — компания, ИНН, сумма». Когда
  деньги пришли по выписке: Root → «Платежи» → «Отметить оплату». Это тот
  же путь, что у уведомления кассы: тариф продлевается, админам уходит
  «Оплата получена», появляется УПД. Отменённый счёт тоже можно отметить
  оплаченным — его могли оплатить уже после отмены.
- Возврат по счёту — переводом на расчётный счёт плательщика; кнопки
  «Вернуть деньги» у счёта нет.
- В приложениях счёт не выставить (как и оплату картой).

## Закрывающие документы (УПД)

УПД статус 2 (передаточный документ, акт; счёт-фактура не составляется)
по форме из письма ФНС ММВ-20-3/96@, как в HASSR: номер — номер заказа,
дата — дата оплаты, сумма — пришедшие деньги, строка — тариф и оплаченный
период, скидка по промокоду указана в строке.

- Выпускается лениво, при первом скачивании («УПД» у платежа в истории и
  у root), для оплаченных боевых платежей с суммой больше нуля. Снимок
  сторон сохраняется в `closing_documents` и дальше не меняется. Если
  покупатель заполнил реквизиты после первого скачивания, снимок без ИНН
  дополняется ими.
- Возврат денег аннулирует документ: PDF скачивается с пометкой
  «АННУЛИРОВАН».
- Скачать может админ своей компании или root; чужой документ — 404.
- Подписи и печати в PDF нет: оригинал с подписью или ЭДО — по запросу
  (так написано внизу документа).

### Реквизиты Исполнителя

GitHub Secrets → Run workflow, как остальные `LEGAL_*`. Чего не хватает,
видно у root: «Касса» → «Счета и УПД». Документы рассчитаны на продавца
без НДС (УСН, ИП): в счёте «Без налога (НДС)», в УПД — статус 2 и «без
НДС» в графах налога. Плательщику НДС понадобится УПД статус 1 — это
отдельная доработка.

| Секрет | Значение |
|---|---|
| `LEGAL_OPERATOR_NAME`, `_INN`, `_OGRN`, `_ADDRESS` | те же, что в оферте |
| `LEGAL_OPERATOR_KPP` | КПП — только у организации |
| `LEGAL_BANK_NAME`, `LEGAL_BANK_BIK` | банк и БИК (9 цифр) |
| `LEGAL_BANK_ACCOUNT`, `LEGAL_BANK_CORR_ACCOUNT` | расчётный и корр. счёт (по 20 цифр) |
| `LEGAL_SIGNER_POST`, `LEGAL_SIGNER_NAME` | подписант; у ИП должность подставится сама |

### PDF

Свой генератор (`server/billing/pdf`), без npm-зависимостей: разбор
TrueType, шрифт вшивается подмножеством (только глифы документа, ~60 КБ
на файл) как CIDFontType2 с Identity-H и ToUnicode — текст ищется и
копируется. Кириллица — DejaVu Sans (свободная лицензия рядом с файлом).
Проверка формы руками: `pdftotext -layout`, `pdftoppm -png`.

## Возвраты

- Возврат кнопкой: Root → «Компании» → «Платежи» → «Вернуть деньги» у
  оплаченного боевого платежа. Нужен `ROBOKASSA_PASSWORD3`. Сервер берёт
  `OpKey` операции через OpStateExt и отправляет полный возврат в
  RefundService (`/Refund/Create`, тело — JWT HS256 на Пароле #3, как в
  официальном плагине). Заказ — «возврат в обработке»; тик оплаты
  спрашивает `/Refund/GetState`: `finished` — заказ «Возвращён», админам
  уходит «Деньги возвращены»; `canceled` — возврат можно отправить снова.
- Повторно, пока касса не ответила по прошлому возврату, отправить нельзя
  (условный UPDATE `refund_status`). Касса не ответила на заявку — статус
  «проверьте кассу», а сверка закончит возврат сама, когда операция станет
  State 60. Если в кабинете кассы видно, что деньги не вернулись, root
  нажимает «Повторить возврат» и вводит «ВЕРНУТЬ»; перед отправкой касса
  спрашивается ещё раз, и при State 60 вторая заявка не уходит.
- «Отправляется» дольше 10 минут (процесс упал посреди отправки) тик
  переводит в «проверьте кассу» и пишет владельцу.
- Тариф после возврата: если это последняя оплата компании (срок не менялся
  после неё), тариф и срок возвращаются к тем, что были до оплаты
  (`plan_before`, `plan_until_before`; `""` — тарифа не было). Если тот срок
  дала оплата, которую уже вернули, откат идёт дальше по цепочке — вернув
  сначала раннюю оплату, потом позднюю, компания не сохранит оплаченный
  период даром. Если после оплаты были другие оплаты или правки, либо
  оплата старше снимка (`plan_before` = NULL), срок не трогаем — владелец
  получит «поправьте срок вручную». Возврат оплаты серии
  выключает автопродление: иначе откат срока сразу вызвал бы новое
  списание.
- Вернули деньги в кабинете Робокассы — нажмите «Проверить в кассе» у
  платежа: State 60 отметит возврат и откатит тариф так же.
- Сумма возврата — по разделу оферты «Возврат». Частичных возвратов кнопкой
  нет: их делают в кабинете кассы, срок тарифа root правит вручную.
