# Должностная инструкция → задачи через диспетчер Ralph

Руководитель в «Сотрудниках» даёт инструкцию человека текстом, файлом Word (.docx)
или Excel (.xlsx). TasksFlow вынимает из неё текст, отдаёт на разбор диспетчеру
Ralph (локальный `codex exec` на машине владельца) и по ответу сам создаёт
сотруднику задачи: регулярные, с днями недели, чек-листами и пометкой «нужно фото».

## Как это устроено

```
TasksFlow (tasksflow.ru)
  │ 1. POST /api/ai/text-jobs  { instructions: промпт, input: инструкция + контекст }
  ▼
ProjectsFlow (projectsflow.ru) — очередь ai_prompt_jobs, mode = text
  ▲ 2. Ralph забирает задание (claim)        │ 3. ai-job-worker.ps1 → Do-Text →
  │                                          │    llm-client.psm1 → codex exec
  └──────────── complete { text: JSON } ◀────┘    (C:\www\ralph на твоей машине)
  │
  │ 4. GET /api/ai/text-jobs/:id?wait=25 — TasksFlow забирает JSON
  ▼
TasksFlow создаёт задачи сотруднику (createTaskForActor: права, аудит, push, WeSetup)
```

Код Ralph под это **менять не нужно**: TasksFlow ходит в готовый Codex-шлюз
ProjectsFlow (`docs/codex-gateway.md` в ProjectsFlow), а Ralph уже исполняет
такие задания веткой `Do-Text` в `ai-job-worker.ps1`. Промпт живёт в TasksFlow
(`server/job-description/prompt.ts`) и уходит полем `instructions`, поэтому его
можно править без выкатки Ralph.

Ответ — тот же JSON с `segments`, что у разбора сообщений Telegram
(`prompts/tasksflow-task.md`), и проходит ту же нормализацию
(`server/telegram/normalize.ts`). Исполнитель — всегда этот сотрудник, премия —
сумма компании по умолчанию, не больше 10 задач. Задачу с тем же названием у
сотрудника второй раз не создаём, поэтому «Повторить» и новая инструкция дублей
не дают.

## Что сделать у себя (по шагам)

### 1. Ralph запущен и берёт короткие задания

На машине с Ralph (`C:\www\ralph`):

1. `codex login` от того же пользователя Windows, под которым работает диспетчер
   (Ralph использует свой CLI в `.runtime/codex`).
2. В `config.local.json`:
   - `"aiPromptJobs": { "enabled": true, ... }` — по умолчанию уже `true`;
   - `"llm": { "engine": "codex", ... }` — по умолчанию уже так.
3. Запустить или перезапустить: команда `ralph` (или `Ralph.cmd` на рабочем столе,
   чтобы видеть лог в окне).

### 2. Ralph — диспетчер шлюза по умолчанию

Шлюз отдаёт задания аккаунту из переменной `AI_PROMPT_DEFAULT_DISPATCHER_EMAIL`
на сервере ProjectsFlow — это должен быть аккаунт, под которым работает Ralph.
Если переменная не задана, `POST /api/ai/text-jobs` отвечает `503`.

### 3. Токен для TasksFlow

На projectsflow.ru: **Профиль → «Доступ для агентов» → «Создать токен»**, scope
**account**. Проектный токен шлюз не пустит (`403`).

Лучше завести отдельный служебный аккаунт без проектов и выдать токен от него:
account-токен видит credentials всех проектов своего аккаунта, а этот будет лежать
в `.env` TasksFlow.

### 4. Проверить шлюз руками

```bash
TOKEN=pfat_...
ID=$(curl -s -X POST https://projectsflow.ru/api/ai/text-jobs \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"instructions":"Ответь одним словом","input":"Как называется столица России?"}' \
  | sed -E 's/.*"id":"([^"]+)".*/\1/')
curl -s "https://projectsflow.ru/api/ai/text-jobs/$ID?wait=55" -H "Authorization: Bearer $TOKEN"
```

Ждём `"status":"succeeded"` за 10–40 секунд. В логе Ralph (`logs/`) — строка
`text done ok=true`. Если через 15 минут `cancelled` с `dispatcher_timeout` —
Ralph не взял задание (не запущен, не диспетчер по умолчанию, выключен
`aiPromptJobs`).

### 5. Токен в TasksFlow на сервере

В `.env` TasksFlow на проде (там же, где `PF_AGENT_TOKEN`):

```
CODEX_GATEWAY_TOKEN=pfat_...
# необязательно, по умолчанию так и есть
CODEX_GATEWAY_URL=https://projectsflow.ru/api
```

Потом `pm2 reload tasksflow --update-env`. Из облачной сессии Claude это делается
скиллом `prod` и только после твоего «да».

Если `CODEX_GATEWAY_TOKEN` не задан, TasksFlow попробует `PF_AGENT_TOKEN` и
`PF_API_URL` от разбора Telegram: шлюз примет их, если этот токен со scope
account.

### 6. Выкатить и проверить

1. Смержить PR — деплой сам прогонит миграцию `npm run create-job-descriptions-table`
   (таблица `job_descriptions`, обязательный шаг в `deploy.yml`).
2. «Сотрудники» → «Добавить сотрудника» → блок «Должностная инструкция» → вкладка
   «Word» → файл → «Добавить сотрудника».
3. В строке человека: «Разбираем инструкцию» → через минуту-две
   «Задач из инструкции: N». Задачи — в «Задачах» у этого сотрудника.
4. У уже добавленных людей — кнопка «Инструкция» в строке.

## Статусы в «Сотрудниках»

| Видно в строке | Что значит | Что делать |
|---|---|---|
| Инструкция ждёт диспетчера | На сервере нет токена шлюза | Шаг 5 |
| Инструкция в очереди | Шлюз временно не принял (429, 5xx, сеть), повторим сами | Подождать; ≥10 неудач — станет ошибкой |
| Разбираем инструкцию | Задание у Ralph | Обычно минута-две |
| Задач из инструкции: N | Готово | — |
| Новых задач в инструкции нет | Модель не нашла обязанностей или все задачи уже были | Проверить текст инструкции |
| Инструкцию не разобрали · Повторить | Причина — в строке под статусом | См. ниже |

Частые причины ошибки:

- «Диспетчер Ralph не взял инструкцию за 15 минут — он запущен?» — шаги 1–2.
- «Токен ProjectsFlow не подходит: нужен токен агента со scope account» — шаг 3.
- «Диспетчер вернул ответ не в том формате» — модель ответила не JSON; «Повторить».

## Лимиты

- Файл до 5 МБ; текст после извлечения — до 30 000 символов.
- Не больше 30 инструкций в час на компанию (TasksFlow) и 300 текстовых заданий
  в час на аккаунт токена (ProjectsFlow).
- TasksFlow ждёт ответ до 20 минут, ProjectsFlow снимает неначатое задание через 15.

## Что сделано и что нет

Сделано в TasksFlow:

- поле «Должностная инструкция» с вкладками «Текст / Word / Excel» и пояснением в
  «Добавить сотрудника»; кнопка «Инструкция» у уже добавленных; статус и
  «Повторить» в строке человека; демо-кабинет показывает «ждёт диспетчера»;
- чтение .docx и .xlsx без новых npm-зависимостей (`server/job-description/office-text.ts`,
  защита от zip-бомбы), .txt в UTF-8 и Windows-1251;
- клиент Codex-шлюза, промпт, очередь в `job_descriptions`, фоновая досылка после
  перезапуска сервера, создание задач без дублей;
- тесты: `tests/job-description*.test.ts`, smoke `script/smoke-job-description.js`;
- весь путь проверен на дев-стенде с настоящей базой и **поддельным** шлюзом,
  который отвечает как Ralph: из Word-файла создались 3 задачи.

Не сделано или не проверено:

- **живой прогон через projectsflow.ru и твой Ralph** — из облака нет доступа к
  твоей машине и нет токена; первый настоящий разбор — после шагов 1–6;
- токен на проде не прописан, PR не смержен — это твоё решение;
- старые .doc/.xls, PDF и сканы не читаются — подсказываем пересохранить в .docx/.xlsx
  или вставить текстом (распознавания картинок нет);
- задачи создаются сразу, без экрана «проверить перед созданием»; поправить или
  удалить их можно в «Задачах»;
- в строке сотрудника видно только число созданных задач, без списка.

В Ralph менять ничего не нужно. Если захочешь, чтобы модель думала дольше на
длинных инструкциях, — `llm.reasoningEffort` в `config.local.json` (общая
настройка для всех коротких заданий Ralph).
