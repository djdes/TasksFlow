# Должностная инструкция → задачи через диспетчер Ralph

Руководитель в «Сотрудниках» даёт инструкцию человека текстом, файлом Word (.docx),
Excel (.xlsx) или PDF — или присылает файл Telegram-боту. Инструкции нет —
задачи подбираются по должности или берутся у коллеги на той же должности.
TasksFlow отдаёт текст на разбор диспетчеру Ralph (локальный `codex exec` на машине
владельца) и получает предложения задач: регулярные, с днями недели, чек-листами,
вопросами с вариантами и разовыми задачами первой недели. Руководитель отмечает
нужные, правит названия и создаёт; задачи прошлой инструкции, которых нет в новой,
можно сразу убрать.

## Как это устроено

```
TasksFlow (tasksflow.ru)  ←  кабинет «Сотрудники» или файл боту в Telegram
  │ 1. POST /api/ai/text-jobs  { instructions: промпт, input: инструкция + контекст }
  ▼
ProjectsFlow (projectsflow.ru) — очередь ai_prompt_jobs, mode = text
  ▲ 2. Ralph забирает задание (claim)        │ 3. ai-job-worker.ps1 → Do-Text →
  │                                          │    llm-client.psm1 → codex exec
  └──────────── complete { text: JSON } ◀────┘    (C:\www\ralph на твоей машине)
  │
  │ 4. GET /api/ai/text-jobs/:id?wait=25 — TasksFlow забирает JSON
  ▼
TasksFlow: предложения → «Проверьте задачи: N» в строке сотрудника
           (и сообщение в Telegram автору со ссылкой /admin/users?review=ID)
  │ 5. «Создать выбранные»
  ▼
задачи сотруднику (createTaskForActor: права, аудит, push, WeSetup)
```

Код Ralph под это **менять не нужно**: TasksFlow ходит в готовый Codex-шлюз
ProjectsFlow (`docs/codex-gateway.md` в ProjectsFlow), а Ralph уже исполняет такие
задания веткой `Do-Text` в `ai-job-worker.ps1`. Промпт живёт в TasksFlow
(`server/job-description/prompt.ts`) и уходит полем `instructions`, поэтому его
можно править без выкатки Ralph. «Как у коллеги» диспетчера не зовёт вовсе —
копирует готовые предложения.

Ответ — JSON `segments`, как у разбора сообщений Telegram, плюс `dueInDays` (разовая
задача первой недели) и пункты чек-листа с `options` (вопрос с вариантами). Его
нормализует `server/job-description/proposals.ts`: исполнитель — всегда этот сотрудник,
вопросы — только у регулярных задач, не больше 12 предложений. Премия — сумма компании
по умолчанию. Задачу с тем же названием у сотрудника второй раз не создаём, в том числе
если руководитель переименовал её после прошлой инструкции.

## Что сделать у себя (по шагам)

### 1. Ralph запущен и берёт короткие задания

На машине с Ralph (`C:\www\ralph`):

1. `codex login` от того же пользователя Windows, под которым работает диспетчер
   (Ralph использует свой CLI в `.runtime/codex`).
2. В `config.local.json`:
   - `"aiPromptJobs": { "enabled": true, ... }` — по умолчанию уже `true`;
   - `"llm": { "engine": "codex", ... }` — по умолчанию уже так.
3. Запустить или перезапустить: команда `ralph` (или `Ralph.cmd` на рабочем столе,
   чтобы видеть лог в окне).

### 2. Ralph — диспетчер шлюза по умолчанию

Шлюз отдаёт задания аккаунту из переменной `AI_PROMPT_DEFAULT_DISPATCHER_EMAIL`
на сервере ProjectsFlow — это должен быть аккаунт, под которым работает Ralph.
Если переменная не задана, `POST /api/ai/text-jobs` отвечает `503`.

### 3. Токен для TasksFlow

На projectsflow.ru: **Профиль → «Доступ для агентов» → «Создать токен»**, scope
**account**. Проектный токен шлюз не пустит (`403`).

Лучше завести отдельный служебный аккаунт без проектов и выдать токен от него:
account-токен видит credentials всех проектов своего аккаунта, а этот будет лежать
в `.env` TasksFlow.

### 4. Проверить шлюз руками

```bash
TOKEN=pfat_...
ID=$(curl -s -X POST https://projectsflow.ru/api/ai/text-jobs \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"instructions":"Ответь одним словом","input":"Как называется столица России?"}' \
  | sed -E 's/.*"id":"([^"]+)".*/\1/')
curl -s "https://projectsflow.ru/api/ai/text-jobs/$ID?wait=55" -H "Authorization: Bearer $TOKEN"
```

Ждём `"status":"succeeded"` за 10–40 секунд. В логе Ralph (`logs/`) — строка
`text done ok=true`. Если через 15 минут `cancelled` с `dispatcher_timeout` —
Ralph не взял задание (не запущен, не диспетчер по умолчанию, выключен
`aiPromptJobs`).

### 5. Токен в TasksFlow на сервере

В `.env` TasksFlow на проде (там же, где `PF_AGENT_TOKEN`):

```
CODEX_GATEWAY_TOKEN=pfat_...
# необязательно, по умолчанию так и есть
CODEX_GATEWAY_URL=https://projectsflow.ru/api
```

Потом `pm2 reload tasksflow --update-env`. Из облачной сессии Claude это делается
скиллом `prod` и только после твоего «да».

Если `CODEX_GATEWAY_TOKEN` не задан, TasksFlow попробует `PF_AGENT_TOKEN` и
`PF_API_URL` от разбора Telegram: шлюз примет их, если этот токен со scope
account.

### 6. Выкатить и проверить

1. Смержить PR — деплой сам прогонит `npm run create-job-descriptions-table`
   (таблица `job_descriptions` с колонками `proposals` и `auto_apply`, обязательный
   шаг в `deploy.yml`).
2. «Сотрудники» → «Добавить сотрудника» → блок «Должностная инструкция» → вкладка
   «Word», «Excel» или «PDF» → файл → «Добавить сотрудника». Либо чип
   «По должности «…»» или «Как у коллеги: …».
3. В строке человека: «Разбираем инструкцию» → через минуту-две «Проверьте задачи: N».
   Нажать → отметить нужные → «Создать». С галочкой «Создать задачи сразу, без
   проверки» задачи появятся без этого шага.
4. Telegram: прислать боту файл инструкции (можно с подписью «для Олега») → выбрать
   сотрудника кнопкой → когда задачи готовы, бот пришлёт «Проверить задачи».
5. Root → «Компании и тарифы» → «Инструкции → задачи»: сколько создано, удалено и
   переименовано — по этому подкручивать промпт.

## Статусы в «Сотрудниках»

| Видно в строке | Что значит | Что делать |
|---|---|---|
| Инструкция ждёт диспетчера | На сервере нет токена шлюза | Шаг 5 |
| Инструкция в очереди | Шлюз временно не принял (429, 5xx, сеть), повторим сами | Подождать; ≥10 неудач — станет ошибкой |
| Разбираем инструкцию | Задание у Ralph | Обычно минута-две |
| Проверьте задачи: N | Предложения готовы | Нажать, отметить, «Создать» |
| Задач из инструкции: N | Создано; нажать — что стало с задачами потом | — |
| Новых задач в инструкции нет | Модель не нашла обязанностей | Проверить текст инструкции |
| Инструкцию не разобрали · Повторить | Причина — в строке под статусом | См. ниже |

Частые причины ошибки:

- «Диспетчер Ralph не взял инструкцию за 15 минут — он запущен?» — шаги 1–2.
- «Токен ProjectsFlow не подходит: нужен токен агента со scope account» — шаг 3.
- «Диспетчер вернул ответ не в том формате» — модель ответила не JSON; «Повторить».
- «В PDF нет текста — похоже, это скан» — нужен .docx или текст (см. ниже).

## Лимиты

- Файл до 5 МБ; текст после извлечения — до 30 000 символов.
- Не больше 12 предложений из одной инструкции, из них не больше 3 разовых задач
  первой недели (срок — до 14 дней).
- Не больше 30 инструкций в час на компанию (TasksFlow) и 300 текстовых заданий
  в час на аккаунт токена (ProjectsFlow).
- TasksFlow ждёт ответ до 20 минут, ProjectsFlow снимает неначатое задание через 15.
- Бот ждёт выбора сотрудника 30 минут.

## Что сделано и что нет

Сделано в TasksFlow:

- поле «Должностная инструкция» с вкладками «Текст / Word / Excel / PDF», чипами
  «По должности» и «Как у коллеги» и галочкой «Создать сразу»; кнопка «Инструкция»
  у уже добавленных; статус, «Повторить» и окно «Задачи из инструкции»;
- проверка перед созданием: галочки, правка названий, «уже есть», «Больше нет в
  инструкции — убрать?» (удаляются только задачи прошлой инструкции, премия у
  выполненных возвращается тем же кодом, что и у удаления задачи);
- вопросы с вариантами в чек-листе («Температура 2–6 °C?» → «Да / Нет») и разовые
  задачи первой недели со сроком;
- чтение .docx, .xlsx, .txt и PDF без новых npm-зависимостей (PDF — потоки FlateDecode,
  потоки объектов, ToUnicode, ширины глифов для пробелов);
- Telegram: файл боту → «чья это инструкция?» кнопками (или имя из подписи) → разбор;
  ссылка «Проверить задачи», когда предложения готовы (и для инструкций из кабинета);
- учёт правок: в окне видно, какие созданные задачи потом удалили или переименовали;
  root — общая статистика и самые частые удаления и переименования;
- тесты `tests/job-description*.test.ts`, smoke `script/smoke-job-description.js`;
- весь путь проверен на дев-стенде с настоящей базой и **поддельным** шлюзом,
  который отвечает как Ralph: PDF → 3 предложения → создано 2 задачи с вопросом и
  сроком; «как у коллеги», «по должности», повторная инструкция с «устаревшими».

Не сделано или не проверено:

- **живой прогон через projectsflow.ru и твой Ralph** — из облака нет доступа к
  твоей машине и нет токена; первый настоящий разбор — после шагов 1–6;
- токен на проде не прописан, PR не смержен — это твоё решение;
- **сканы и фото инструкций не распознаются**: в шлюзе ProjectsFlow текстовые задания
  принимают только текст. Чтобы читать сканы, нужно, чтобы шлюз принимал картинки
  (`/api/ai/text-jobs` с вложениями) и Ralph отдавал их в `codex exec -i …` — это
  правка ProjectsFlow и Ralph, в TasksFlow её не сделать;
- старые .doc/.xls не читаются — подсказываем пересохранить в .docx/.xlsx;
- PDF с нестандартными шрифтами без таблицы ToUnicode (редко, старые генераторы)
  дают понятную ошибку, а не текст.

В Ralph менять ничего не нужно. Если захочешь, чтобы модель думала дольше на
длинных инструкциях, — `llm.reasoningEffort` в `config.local.json` (общая
настройка для всех коротких заданий Ralph).
