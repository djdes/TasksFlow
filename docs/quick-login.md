# QR-код для входа в организацию

В меню кабинета — «QR-код для входа» (`/admin/quick-login`). Доступен
администратору, руководителю WeSetup и ролям с правом ставить задачи,
добавлять сотрудников или принимать выполненное.

Нажмите «Создать QR-код входа», выберите А4 или этикетку 58 × 40 мм и
«Печатать». Диалог браузера позволяет также сохранить PDF. Для этикетки
нужен соответствующий размер бумаги в драйвере принтера, масштаб 100%,
без колонтитулов. Повторная печать использует ту же постоянную ссылку.

Сотрудник сканирует QR камерой телефона, выбирает себя (есть поиск по имени
и должности) и вводит личный PIN. После входа открывается обычный кабинет
с его задачами и правами. На общем устройстве можно явно выйти из текущего
аккаунта и выбрать другого сотрудника.

QR содержит случайную ссылку организации, без PIN и телефонов. По ссылке
видны имена и должности: распечатки предназначены для размещения внутри
организации. Вход проверяет принадлежность сотрудника к организации и
использует общий счётчик неверных PIN и блокировку. Root через QR не входит.
Если PIN ещё нет, его задаёт руководитель через «Сотрудники»; публичный
список не позволяет создавать или сбрасывать PIN.

## Развёртывание

`npm run create-company-login-links` создаёт только новую таблицу
`company_login_links` (`company_id` — первичный ключ, `token` — уникальный).
Скрипт идемпотентный, существующие таблицы и выданные ссылки не меняет.
Он добавлен обязательным шагом в safe migrations деплоя.

## Проверка

- API: `npm test -- tests/quick-login.test.ts tests/cabinet-nav.test.ts`.
- Интерфейс: `npm run build`, затем `SMOKE_ONLY=quick-login npm run smoke`
  (в PowerShell: `$env:SMOKE_ONLY='quick-login'; npm run smoke`).

Smoke подменяет API: проверяет выбор сотрудника, ошибки, PIN, блокировку,
смену аккаунта, права, desktop/mobile и обе темы. PDF и снимки лежат в
`output/playwright/quick-login-*`; у PDF проверяются физические размеры и
ровно одна страница. Реальная БД и аппаратный принтер этим не проверяются.
