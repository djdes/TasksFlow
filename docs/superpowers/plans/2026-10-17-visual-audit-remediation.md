# План исправления видимых багов TasksFlow

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Исправить шесть воспроизводимых дефектов, подтверждённых браузерными снимками, и сохранить рабочие сценарии сайта.

**Architecture:** Сохранить React SPA, публичный SSR и текущий Express API. Исправить согласованность клиентского кэша и прав, стек модальных окон, контракт очереди проверки, адаптивную строку сотрудников и обработку ошибок приглашений. Не проводить общий редизайн и не менять схему БД.

**Tech Stack:** React 18, TypeScript, TanStack Query 5, wouter, Radix, Vaul, Tailwind, Express, Drizzle, MySQL, Vitest, Playwright CLI.

**Spec:** [Доказательства и воспроизведение](../../../output/playwright/audit-2026-10-17/findings.json), [визуальный отчёт](../../../output/playwright/audit-2026-10-17/index.html), исходное поручение пользователя о визуально подтверждённых багах.

**Статус:** Только план. Код приложения не изменён. Выполнение исправлений не начиналось.

## Ограничения

- В список исправлений входят только BUG-01—BUG-06 с визуальным воспроизведением. Остальные найденные в коде зоны риска не объявляются багами.
- Сохранять ограничения компаний, исполнителей и manager scope на сервере. Разрешение открыть форму не означает разрешение назначать задачи чужим сотрудникам.
- Не выполнять `setup-db`, `db:push`, `DROP`, force push или восстановление дампа поверх рабочей БД. Для этих исправлений миграции не нужны.
- Использовать существующий `components/ui/dialog.tsx`: desktop — диалог, mobile до 768 px — шторка. Проверять Escape, стек, фокус и свайп.
- Загрузка — PageSkeleton/ListSkeleton; ошибка — сообщение с повтором. При фоновом обновлении сохранять уже полученные данные.
- Проверять обе темы, 360/390 px и desktop, длинные имена/формы, системное уменьшение движения и `tf_motion_enabled=false`.
- Не добавлять зависимости, постоянный `will-change`, `transition: all`, искусственные задержки загрузки или скрытие переполнения для маскировки обрезанных действий.
- Рабочая директория изначально содержала чужой untracked `uploads/task-9999-1778040026229-4ef614c7495a0a38.jpg`; его не трогать.

## Review Focus

1. Выполнение с проверкой, повторный complete и получение премии другим участником не должны приводить к локальному «прибавить price» без серверного подтверждения. Проверить в задаче 1.
2. `managedWorkerIds=null`, `[]`, непустой массив и повреждённый JSON должны одинаково трактоваться dashboard, формами и сервером. Проверить в задаче 2.
3. Escape при двух открытых уровнях закрывает только верхний; смена задачи и закрытие родителя не оставляют прежнее фото. Проверить в задаче 3.
4. Доступ проверяющего к имени автора конкретной работы не расширяет `/api/users` и не раскрывает сотрудников другой компании. Проверить в задаче 4.
5. Нулевая премия, положительная премия, длинное имя и маленькая ширина проверяются вместе; транспортный сбой приглашения не меняет его бизнес-статус. Проверить в задачах 5 и 6.
